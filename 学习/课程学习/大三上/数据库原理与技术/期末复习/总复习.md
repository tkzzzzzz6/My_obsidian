# 数据库系统概述
信息:现实客观事物在人脑中的抽象反映
数据:描述客观事物的可存储并具有明确意义的符号序列
数据与语义密不可分
信息是数据的内涵,数据是信息的载体
数据库管理技术阶段:
人工管理阶段,文件管理阶段(数据和程序物理分离),数据库管理阶段(整体结构化)

## 数据模型
数据模型描述的内容:数据结构,数据操作,数据约束
分为概念模型,逻辑模型和物理模型
概念模型:信息世界的建模,现实世界到信息世界的第一层抽象,不依赖于具体的计算机系统和数据库关系系统
典型的表示方法,实体联系方法 ER模型
逻辑模型:将概念模型转化为具体的数据模型的过程,按照概念模型建立基本的 ER 图,选定数据库管理系统支持的数据模型(层次模型,网状模型,关系模型,面向对象模型,)
物理模型是对真实数据库的描述(数据在存储介质上的组织结构,存储方式,和存取方法)
## 数据库系统的三级模式结构
外模式(external schema),模式(schema),内模式(internal schema)
模式:逻辑模式,综合所有的数据需求,从全局的角度对数据库中的全部数据的逻辑结构和特征的总体描述,所有用户的公共数据的视图(全局视图),只能有 1 个
外模式:子模式,用户模式,程序员和最终用户最终能看见和使用的局部数据的逻辑结构和特征描述,通常是模式的子集,可以有多个,但一个应用程序只能有1 个外模式
> 好处:简化程序设计和数据使用,只用关系和自己有关的数据,也不用关系存储结构
用户只能操作与其有关的数据,有利于数据的安全性
同一模式能派生多个外模式,有利于数据的独立与共享

内模式:存储模式,物理模式,数据物理结构和存取方式的底层描述

## 数据库的二级映像与数据独立性
模式/外模式:
对每个外模式,有1 个模式/外模式映像,定义外模式与模式之间的对应关系,当模式改变时,对模式/外模式做相应更改,使外模式不变,基于外模式的应用程序不需要修改,实现了数据与程序的逻辑独立性(数据的逻辑独立性)

内模式/模式:
定义数据全局逻辑结构与存储结构之间的对应关系,是唯一的,当数据库的存储结构改变了,修改内模式/模式映像,使模式保持不变,事项数据的物理独立性

数据库的二级映像功能保证了应用程序的稳定性,除非应用程序的需求发生改变,否则应用程序一般不需要修改

# 关系数据库规范理论

## 规范化与数据依赖

### 关系模式五元组

- R(U, D, DOM, F, I)
  - U: 属性集合
  - D: 属性域集合
  - DOM: 属性到域的映射
  - F: 函数依赖集合
  - I: 关系实例集合

### 数据依赖

- 函数依赖 (FD): X -> Y
- 多值依赖 (MVD): X ->> Y

### 函数依赖分类

- 平凡/非平凡函数依赖
  - 平凡: Y ⊆ X (如 AB -> A)
  - 非平凡: Y ⊄ X
- 完全/部分函数依赖
  - 完全: Y 完全依赖于码 X
  - 部分: Y 依赖于 X 的真子集
- 传递函数依赖
  - X -> Y, Y -> Z, 且 Y 不是码, 则 X -> Z 为传递依赖

### 关键概念

- 超码: 能唯一确定元组的属性集
- 候选码: 最小超码
- 主属性: 出现在某个候选码中的属性
- 非主属性: 不在任何候选码中的属性
- 决定因子: 函数依赖左部

## 关系模式的规范化

### 范式层级

- 1NF ⊆ 2NF ⊆ 3NF ⊆ BCNF ⊆ 4NF ⊆ 5NF
- 目的: 消除插入异常、删除异常、修改复杂、数据冗余

### 1NF

- 关系中所有属性都是不可再分的基本数据项

### 2NF

- 属于 1NF
- 每个非主属性完全函数依赖于任何一个候选码
- 不满足 2NF 的典型问题
  - 插入异常
  - 删除异常
  - 数据冗余
  - 修改异常

### 3NF

- 属于 2NF
- 非主属性不传递函数依赖于候选码

### BCNF

- 属于 1NF
- 每个决定因子都包含候选码
- 消除主属性对非码的部分/传递依赖

### 规范化流程 (记忆版)

- 属性不可分 -> 1NF
- 消除非主属性对码的部分依赖 -> 2NF
- 消除非主属性对码的传递依赖 -> 3NF
- 消除主属性对非码的部分/传递依赖 -> BCNF

### 分解的两个性质

- 无损连接: 分解后可通过连接恢复原关系
- 依赖保持: 分解后依赖可由各子关系的依赖推出

### 完整性

- 实体完整性: 主码非空且唯一
- 参照完整性: 外码与主码一致或为空
- 用户定义完整性: check/触发器等

## 复习速记

- 2NF 解决: 非主属性对码的部分依赖
- 3NF 解决: 非主属性对码的传递依赖
- BCNF 解决: 主属性对非码的依赖
- 无损连接与依赖保持是分解的核心标准

# 关系数据库标准语言 SQL

## SQL 特点

- 综合统一
- 高度非过程化
- 面向集合的操作方式
- 一套语法支持交互与嵌入式
- 简单易学
- 支持 DDL / DML / DCL

## 数据定义 (DDL)

### 创建基本表

```sql
create table sc (
    sno char(9),
    cno char(4),
    grade smallint,
    primary key (sno, cno),
    foreign key (sno) references student(sno),
    foreign key (cno) references course(cno)
);
```

### 修改/删除表 (常见写法)

```sql
alter table student add sphone char(11);
alter table student drop column sphone;
drop table sc;
```

### 索引

```sql
create unique index stusno on student(sno);
create unique index coucno on course(cno);
create unique index scno on sc(sno asc, cno desc);
drop index scno;
```

## 数据查询 (DQL)

### 单表查询

```sql
select sname, sage from student;
select * from student;
select 2025 - sage as byear from student;
select lower(sdept) from student;
select sname, sage from student where sage < 20;
select sname, sage from student where sage between 20 and 30;
select sname, sage from student where sdept in ('cs', 'ee');
select sno from student where sname like '张%';
select sno from student where sname like '_棵%';
select sno from sc where grade is null;
select sname from student where sdept = 'cs' and sage < 20;
select sname from student order by sdept, sage desc;
```

### 聚集与分组

```sql
select count(*) from student;
select avg(grade) from sc;
select max(grade) from sc where cno = '1';
select cno, count(sno) from sc group by cno;
select sno from sc group by sno having count(cno) > 3;
```

- where 子句中不能出现聚集函数
- 分组后的条件使用 having

### 连接查询

```sql
select student.*, sc.*
from student, sc
where student.sno = sc.sno;

select s.*, sc.cno, sc.grade
from student as s
left join sc on s.sno = sc.sno;

select student.sno, student.sname, course.cname, sc.grade
from student
left join sc on student.sno = sc.sno
left join course on sc.cno = course.cno;
```

### 嵌套查询

- 一个 `select-from-where` 语句称为查询块
- 将查询块嵌入到另一个查询块的 where/having 子句中称为嵌套查询

```sql
select sname from student where sno in (
    select sno from sc where cno = '2'
);

select * from student where sdept in (
    select sdept from student where sname = 'smith'
);

select sno from student where sno in (
    select sno
    from sc left join course on sc.cno = course.cno
    where cname = 'is' and grade < 60
) and sno in (
    select sno
    from sc left join course on sc.cno = course.cno
    where cname = 'ma' and grade < 60
);

select sname, sage
from student
where sdept != 'cs'
  and sage < any (select sage from student where sdept = 'cs');
```

### 集合查询

- 并/交/差操作要求列数一致且对应列类型兼容

```sql
-- 自动去除重复元组
select * from student where sdept = 'cs'
union
select * from student where sage < 19;

-- 保留重复元组
select * from student where sdept = 'cs'
union all
select * from student where sage < 19;

select * from student where sdept = 'cs'
intersect
select * from student where sage < 19;
```

## 数据更新 (DML)

### 插入

```sql
insert into student(sid, sname, sage, sdept, sgender)
values ('005', 'tk', 20, 'cs', 'm');

create table dept_grade_avg (
    dept char(10),
    avg_grade smallint
);

insert into dept_grade_avg(dept, avg_grade)
select sdept, avg(grade)
from student left join sc on student.sno = sc.sno
group by sdept;
```

### 修改

```sql
update student set sage = 20 where sno = '20230000';
update student set sage = sage + 1;
update sc
set grade = 100
where (select sdept from student where student.sno = sc.sno) = 'cs';
```

### 删除

```sql
delete from student where sno = '20230000';
```

- delete 和 update 的条件使用方式相似

## 视图

### 基本概念

- 视图只存放定义, 数据仍在基本表中
- 基本表被删除后, 相关视图无法使用

### 建立与删除

```sql
create view student_cs as
select * from student where sdept = 'cs'
with check option;

drop view student_cs cascade;
```

### 查询与更新 (视图消解)

- 有效性检查: 查询涉及的表/视图是否存在
- 从数据字典取出视图定义, 转为等价的基本表查询
- 只存定义, 不执行视图中的 select 语句
- 执行修正后的查询或更新

```sql
select sno, sname from is_student where sage < 20;
-- 视图消解后等价于
select sno, sname from student where sage < 20 and sdept = 'is';

update is_student set sname = 'zhangsan' where sid = '20230001';
-- 视图消解后等价的语句
update student set sname = 'zhangsan' where sid = '20230001' and sdept = 'is';
```

### 视图的作用

- 简化用户操作
- 多角度查看同一数据
- 提供一定程度的逻辑独立性 (模式/外模式)
- 对机密数据提供一定程度的安全保护
- 让复杂查询更易表达和理解

## 复习速记

- 单表查询、连接查询、嵌套查询、集合查询是 DQL 核心
- DDL 关注表/索引/约束定义, DML 关注增删改
- 视图只存定义, 更新依赖视图消解

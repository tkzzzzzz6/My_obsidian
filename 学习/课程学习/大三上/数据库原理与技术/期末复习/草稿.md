一个完成的数据库系统包含
用户:最终使用数据库的人是数据库的服务对象,可以通过应用系统或查询语言访问数据,是数据库存在的目录和服务对象
应用系统/开发工具:应用系统是为特定业务需求设计的软件,应用开发工具是支持开发者设计和访问数据库的应用程序,是用户和数据库系统之间的桥梁
数据库管理系统:DBMS,提供 DDL,DML,数据控制等功能,复制数据安全性一致性,完整性和并发控制,是数据库系统的核心软件
操作系统 OS:管理计算机硬件资源,为 DBMS提供底层支持,是数据库操作系统赖以运行的基础平台
数据库 DB:存储经组织的数据集合,常以表的形式存放,是数据库的基础
数据库管理员 DBA:负责数据库设计,运行和维护,包括权限管理,性能优化,备份与恢复,是数据库的管理者
总结:用户通过应用系统/开发工具与数据库管理系统交互,DBMS 借助操作系统管理和操作底层数据库,整个系统由数据库管理员管理和维护

数据模型的三大要素:数据结构数据操控,完整性约束
数据结构:描述数据对象及其相互关系,如表,记录,字段,定义了数据的组织方式
数据操作:对数据进行增删改查等操作的集合,规定了如何操作和处理数据
完整性约束:保证数据的正确性和完整性,有实体完整性,参照完整性和用户自定义完整性,如(主键唯一且不能为空,外键必须在其他关联的表中的属性中的值或者为空,用户自己定义的数据结构如 mysql 中的 check option 选项)
其中最重要的是数据结构,因为它决定了数据的组织形式,是数据操作和完整性约束的基础

数据定义功能:提供数据定义语言 DDL,用于定义数据库模型,表结构,视图,索引等
数据操纵功能:提供数据操纵语言 DML,支持查询,添加,删除,修改等数据操作
数据控制功能:提供安全性控制如用户权限管理,完整性约束,并发控制和恢复功能
事务管理功能:保证事务的 ACID 特性原子性,一致性,隔离性,持续性
数据存储和管理功能:负责数据的物理存储,索引,优化和缓存等底层管理
数据库的维护功能:提供备份与恢复,性能优化,日志管理等功能

关系模型中有 3 中完整性约束
实体完整性:若属性或属性组A 是基本关系R 的主键,则A 的值应该唯一且不为空
即关系中的元组可以按照主键唯一标识
参照完整性:设F 是基本关系R 中的一个或者一组属性,但不是 R 的主键,如果 F 和基本关系S 的主键K 相对应,则F 为基本关系R 的外键,并称其为 基本关系R 的参照关系

用户自定义完整性:用户定义完整性是针对某一特定关系数据库的约束条件,它反映具体应用所涉及的数据必须满足的语义要求

数据库的安全性指的是防止非法使用造成的数据泄露修改或者破坏

5 种安全控制计数,
用户标识和鉴别:第一道大门,系统需要知道用户是谁,常用的方法有但用户名鉴别法,用户名和口令鉴别法,透明公式鉴别法
用户存取和管理权限控制:核心机制,即使进入了系统也不代表能看所有数据,系统根据预定权限,决定用户是否对对应的表或者字段有读写,改操控
常用的方法有定义用户权限,合法权限检查,自主访问控制和强制访问控制
视图机制:一种隐藏思想的手段,通过定义视图.只展示用户该看的数据,隐藏敏感数据
数据加密:最后的防线,将明文数据通过加密方式转化为密文,即使获取了也难以得到原有的数据
审计:秋后算账的监控机制,系统自动记录用户对数据库的关键操作,一旦发生安全事故,管理员可以立即追责

事务:用户操作数据库的基本单元,也是数据库恢复和并发控制的基本单位

原子性:事务中的操作要么全部成功要么中间出错后全部回滚,不允许只做一半的情况
一致性:事务的执行结果只能是数据库从一个一致性状态转换到另一个一致性状态,守恒,不能凭空增加或消失

隔离性:多个事务并发执行时,一个事务不能的执行不能影响其他事务,隔离性没处理 好会导致读脏数据的问题

持久性:事务一旦成功,也对数据库的改变是永久的


三种不一致问题:
丢失修改:两个事务同时读入同一数据,并同时进行修改,后提交的事务覆盖先提交的事务
读脏数据:A 读数据后,B 修改但未提及交的数据,B 回滚,A 读的数据无效
不可重复度:A 读数据后,B 修改或删除了该数据,A 再次读是发现不一致,
解决方法采用封锁技术
排他锁:X,共享锁:S
1. 当一个事务进行写是,对改数据上 X 锁直至事务完成,解决丢失修改
2. 读是,上S 锁,读完立即释放,解决读脏数据
3. 读时,上 S锁,事务结束才释放,不可重复读

日志的作用:主要用户数据库的恢复,也可用户审计和系统性能评价

每一条日志记录了事务的标识,哪个事务,操作类型,操作对象,旧值用于 undo,新值,用户 redo

登记日志需要遵循的两种原则

登记的次序严格按照并发事务的执行次序:
只有按照并发执行事务的真实执行的时间登记日志,数据库的恢复时才可能精准还原事务执行的原始逻辑,避免数据不一致

必须先写日志再写数据库
如果先写数据库,但写日志时系统崩溃了,数据库中以后的修改日志还来不及记录,重启后的系统不知道操作执行过,无法进行 undo,破坏了数据库事务中的原子性

3 类故障:
事务故障:运算溢出,违反约束,死锁
恢复:利用日志文件进行 undo,系统反向扫描日志文件,找到该事务对应的更新操作,将数据库恢复至旧值

系统故障:CPU,操作系统故障,停电
恢复:重启时进行 undo+redo 操作,
对崩溃时未提交的事务执行 Undo,保证原子性
对崩溃前已提交的事务但未写入磁盘的事务执行 redo 操作,保证持久性

介质故障,磁盘损坏
恢复:重装副本,重做日志
先装入最新的后备副本,将数据库恢复至备份时的状态
装入备份后的日志文件副本,执行 redo,执行备份以来已提交的所有事务,将数据库状态恢复至故障发生前

需求分析:任务是准确了解与分析用户对系统的需求(数据需求和处理需求),要详细调查现实世界要处理的对象和原系统的概况,形成需求说明书
概念结构设计:将需求分析得到的用户需求抽象为信息结构(概念模型),常使用 er 图或者 ERD 图表示
逻辑结构设计:将概念结构转化为 DBMS 中所支持的如关系模型的数据模型,并进行规范化
物理结构设计:将逻辑结构模型选择一个最适合应用环境的物理结构,包括存储结构和存取方式
数据库实施:根据逻辑结构和物理结构设计结果,建立数据库,编址和调试应用程序,将数据库入库进行测试
数据库运行和维护:在数据库运行过程中,进行日常维护,性能监控,转储恢复,必要时进行数据库重组和重构

DBA数据库管理员的缩写:是从事维护和管理数据库的相关工作人员,贯穿从数据库从设计,实施,运行和维护,升级的全生命周期

数据库设计:决定数据库中的信息内容和结构,决定数据库的存储方式,表,视图,索引
定义数据安全和和完整性:确保数据的安全,定义用户的权限,防止合法用户的非法操作
监控数据库的使用和运行:监控指标和响应时间,分析查询语句,进行优化
数据库的改进和重组:随需求的变化,调整数据库结构,进行数据迁移和重组

备份与恢复:指定合理的备份策略,在数据库出现异常的时候迅速响应,进行故障排除和数据恢复,确保数据库的可用性和完整性


## 一、白盒测试与黑盒测试


① 测试原理:

白盒测试又称结构测试或逻辑驱动测试。根据程序内部逻辑结构、控制流程、条件判断和执行路径来设计测试用例。测试人员需要了解代码实现，通过检查程序中的语句、判定、条件、路径、循环和异常处理，判断程序内部操作是否符合设计要求。核心思想是：从程序内部结构出发，尽可能覆盖程序的逻辑路径。

黑盒测试又称功能测试或数据驱动测试。不考虑程序内部结构，只根据需求规格说明、功能描述、接口定义和输入输出关系来设计测试用例。测试人员只关注输入数据后系统是否产生期望输出。核心思想是：从用户和功能需求角度出发，验证软件外部行为是否符合要求。

② 适用阶段:

白盒测试主要适用于单元测试阶段，也可用于集成测试中的重点模块检查。在编码完成后，测试人员或开发人员可以针对函数、类、模块内部逻辑设计测试用例，检查语句、判定、条件和基本路径是否被覆盖。

黑盒测试主要适用于集成测试、系统测试、确认测试和验收测试阶段。在这些阶段，测试重点不再只是代码内部逻辑，而是系统功能是否满足需求、接口是否正确、业务流程是否完整、用户操作是否符合预期。

在大型软件项目中，通常按照阶段组合使用。需求分析阶段主要采用黑盒测试思想，设计业务场景、等价类、边界值和异常输入；编码和单元测试阶段主要采用白盒测试，检查模块内部逻辑；集成测试阶段二者结合，既检查接口输入输出，也检查模块调用关系和数据流；系统测试和验收测试阶段以黑盒测试为主，模拟真实用户业务流程；回归测试阶段重新执行已有测试用例，防止修改引入新的错误。

③ 测试侧重点:

白盒测试的侧重点是程序内部结构。它重点检查模块接口、局部数据结构、重要执行路径、边界条件和错误处理，主要发现代码逻辑错误、分支遗漏、路径遗漏、循环边界错误和异常处理错误。常用方法包括语句覆盖、判定覆盖、条件覆盖、条件组合覆盖、路径覆盖和基本路径测试。

黑盒测试的侧重点是软件外部功能。它重点检查功能是否满足需求、输入是否合法、输出是否正确、业务流程是否完整、异常输入是否能被正确处理。常用方法包括等价类划分、边界值分析、判定表、因果图、场景法和错误推测法。

二者侧重点不同，但互相补充。白盒测试能深入代码内部，发现隐藏的逻辑问题；黑盒测试能从用户角度发现功能错误和需求实现错误。只做白盒测试，可能代码路径覆盖较好，但仍然漏掉需求理解错误；只做黑盒测试，可能功能表现正常，但内部隐藏分支和异常路径没有被充分检查。

④ 具体软件开发场景

电商系统为例，优惠券计算模块适合使用白盒测试。因为该模块内部逻辑较复杂，可能包含满减、折扣、会员等级、优惠叠加、优惠互斥等多个分支。测试人员需要根据代码结构设计用例，覆盖每个判断条件和执行路径，防止出现折扣计算错误。

下单支付流程则适合使用黑盒测试。测试人员可以从用户角度设计场景，如普通用户下单、VIP 用户下单、优惠券过期、库存不足、支付失败、重复支付、取消订单等，检查系统外部表现是否符合业务规则。

在大型软件项目中，应采用“低层模块偏白盒，高层业务偏黑盒”的策略。核心算法、复杂逻辑和高风险模块加强白盒覆盖；用户高频操作、业务流程和异常输入加强黑盒测试。二者结合使用，才能既保证代码内部逻辑可靠，又保证软件外部功能符合需求，从而最大化保障测试质量。


## 二、软件测试的目标是发现错误

“为证明程序正确而测试”是一种确认式测试思想。它的目的主要是证明程序能够正常运行，因此测试人员容易选择正常输入、典型场景和程序容易通过的测试数据。这种思路的问题是只能说明程序在已选用例下没有暴露错误，不能说明程序绝对正确。例如充值系统只测试 100、500、1000 等合法金额，即使全部通过，也不能证明系统没有输入校验问题。

“为发现错误而测试”是一种更符合软件测试本质的思想。它的目标不是证明程序没有问题，而是主动寻找程序可能失败的情况。测试人员会重点选择边界值、非法输入、异常操作、极端数据和复杂组合条件。例如充值系统不仅要测试 50、1000、2000，还要测试空输入、负数、小数、字符、49、51、2001 等异常数据，这些用例更容易暴露错误。

从软件工程规范看，“为发现错误而测试”更合理。原因是软件测试无法穷尽所有输入，也无法证明程序绝对正确，只能在有限测试范围内尽可能发现错误。软件工程强调风险控制，测试的价值在于尽早发现缺陷、降低修复成本、防止错误进入生产环境。软件测试的核心目标应是发现错误，同时为软件质量评价提供依据。

## 三、折扣函数白盒测试

定义基本条件：
- A 表示 `member_level >= 3`
- B 表示 `total_amount >= 1000`
- C 表示 `is_birthday == true`
- D 表示 `member_level >= 2`。

程序中的主要判定是 `A && B`、`C` 和 `D`。

① 语句覆盖:每条可执行语句至少执行一次

 - S1：(3, 1000, true) → 执行 8 折和生日 7 折 → 0.56
 - S2：(2, 500, false) → 执行非生日会员 9 折 → 0.90

② 判定覆盖:每个判定的真假分支至少执行一次

- D1：(3, 1000, true) → A&&B=T，C=T → 0.56
- D2：(2, 500, false) → A&&B=F，C=F，D=T → 0.90
- D3：(1, 500, false) → A&&B=F，C=F，D=F → 1.00

③ 条件覆盖:每个基本条件真假至少执行一次

- C1：(3, 1000, true) → A=T，B=T，C=T → 0.56
- C2：(1, 1000, false) → A=F，B=T，C=F，D=F → 1.00
- C3：(3, 500, false) → A=T，B=F，C=F，D=T → 0.90

④ 条件组合覆盖:复合条件 A&&B 的所有组合至少执行一次

- CC1：(3, 1000, true) → A=T，B=T → 0.56
- CC2：(3, 999, false) → A=T，B=F → 0.90
- CC3：(1, 1000, false) → A=F，B=T → 1.00
- CC4：(1, 999, true) → A=F，B=F → 0.70

⑤ 路径覆盖:每条可行路径至少执行一次

- P1：(3, 1000, true) → 0.56
- P2：(3, 1000, false) → 0.72
- P3：(1, 500, true) → 0.70
- P4：(2, 500, false) → 0.90
- P5：(1, 500, false) → 1.00

⑥ 基本路径覆盖:覆盖 V(G) 条线性独立路径

判定节点数为 3，所以 V(G)=3+1=4。

- BP1：(3, 1000, true) → 0.56
- BP2：(3, 1000, false) → 0.72
- BP3：(1, 500, true) → 0.70
- BP4：(1, 500, false) → 1.00

路径覆盖中有一条理论路径不可行， `A&&B=true，C=false，D=false`。当 `A&&B=true` 时，说明 `member_level >= 3`，因此必然满足 `member_level >= 2`，所以 D 不可能为 false。

## 四、校园一卡通充值系统黑盒测试

系统的合法输入必须同时满足四个条件：

输入为正整数，金额不低于 50 元，金额不高于 2000 元，并且金额是 50 的整数倍。

有效等价类为：X 是正整数，50 <= X <= 2000，且 X 是 50 的整数倍。


| 输入成分   | 有效等价类              | 无效等价类                                         |
| ------ | ------------------ | --------------------------------------------- |
| 输入内容格式 | 正整数（1）             | 空输入（2）<br>有非数字字符（3）<br>小数（4）<br>负数（5）<br>0（6） |
| 金额范围   | 50 到 2000 之间的整数（7） | 小于 50 的整数（8）<br>大于 2000 的整数（9）                |
| 金额倍数规则 | 50 的整数倍（10）        | 非 50 的整数倍（11）                                 |

合法输入必须同时覆盖（1）（7）（10），即输入为正整数，金额在 50 到 2000 之间，并且是 50 的整数倍。


最小完备黑盒测试用例集如下：

| 用例     | 覆盖类    | 期望值              |
| ------ | ------ | ---------------- |
| 50     | 1，7，10 | 充值成功             |
| 1000   | 1，7，10 | 充值成功             |
| 2000   | 1，7，10 | 充值成功             |
| 空输入    | 2      | 输入不能为空           |
| abc    | 3      | 金额必须为正整数         |
| 100abc | 3      | 金额必须为正整数         |
| 100.5  | 4      | 金额必须为正整数         |
| -50    | 5      | 金额必须为正整数         |
| 0      | 6      | 金额必须为正整数         |
| 49     | 8      | 单次充值最低金额为 50 元   |
| 2001   | 9      | 单次充值最高金额为 2000 元 |
| 51     | 11     | 充值金额必须为 50 的整数倍  |
| 1999   | 11     | 充值金额必须为 50 的整数倍  |
| ￥100   | 3      | 金额必须为正整数         |

说明：50、1000、2000 分别覆盖最低合法值、典型合法值和最高合法值；49 和 2001 覆盖边界外侧离点；51 和 1999 覆盖范围内但非 50 倍数的情况；空输入、字符、小数、负数、0 和带符号金额用于覆盖常见非法输入。

## 第二题
![1765875228346.png](https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/1765875228346.png)
![1765875272419.png](https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/1765875272419.png)
这题的关键点有两个：

1. **转移指令是相对寻址**：转移目标地址 = **(当前PC取完该指令后的PC值)** + **相对位移量disp**
    
2. **CPU每取1个字节，PC自动+1**。该转移指令共3字节，所以**取完指令后**
    
    PC_{\text{after}} = PC_{\text{before}} + 3
    

并且相对位移量 disp 用 **16位补码** 表示，其中：

- 第2字节 = disp 的 **低8位**
    
- 第3字节 = disp 的 **高8位**
    

---

## **通用解题步骤（套公式）**

  

给定：PC当前值 = PC，目标地址 = T

1. 取完3字节后的PC：
    
    PC_{\text{after}} = PC + 3
    
2. 计算相对位移（有符号）：
    
    disp = T - PC_{\text{after}}
    
3. 把 disp 写成 **16位补码**（十六进制 4 位）
    
4. **低8位给第2字节，高8位给第3字节**
    

---

## **(1) PC=256(十进制)，转移到290(十进制)**

  

**步骤1：**

PC_{\text{after}} = 256 + 3 = 259

  

**步骤2：**

disp = 290 - 259 = 31

  

**步骤3：** 31 的16位补码就是普通二进制：

31_{10} = 001F_{16}

  

**步骤4：拆成低8位/高8位**

- 低8位（第2字节）= **1Fh**
    
- 高8位（第3字节）= **00h**
    

  

✅ **参考答案：第2字节 = 1FH，第3字节 = 00H**

---

## **(2) PC=128(十进制)，转移到110(十进制)**

  

**步骤1：**

PC_{\text{after}} = 128 + 3 = 131

  

**步骤2：**

disp = 110 - 131 = -21

  

**步骤3：把 -21 写成16位补码**

先写 +21：

21_{10} = 0015_{16}

求补码（取反+1）：

- 取反：FFEA
    
- +1：FFEB
    

  

所以：

-21 = FFEB_{16}

  

**步骤4：拆成低8位/高8位**

- 低8位（第2字节）= **EBh**
    
- 高8位（第3字节）= **FFh**
    

  

✅ **参考答案：第2字节 = EBH，第3字节 = FFH**

---

### **最终汇总**

- (1) **1FH，00H**
    
- (2) **EBH，FFH**

### 第三题
![53dee51aabb1a17696378ff4b5b401f1.jpg](https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/53dee51aabb1a17696378ff4b5b401f1.jpg)
![f25c4b3f9be7bd6b35e493772900b5c7.jpg](https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/f25c4b3f9be7bd6b35e493772900b5c7.jpg)
下面我把**求解思路 + 每条指令的完整计算步骤**写清楚（这类题的依据就是：**把16位指令按 OP(6) + I(2) + D(8) 切字段**，再按 I 指定的寻址方式算 EA）。

---

## **1. 题目已知与规则**

  

**指令格式（16位）：**

- OP：6 位（最高 6 位）
    
- I：2 位（紧接 OP 的 2 位）
    
- D：8 位（最低 8 位，形式地址/位移）
    

  

也就是位分布：
$$\underbrace{b_{15}\cdots b_{10}}_{\text{OP(6)}}\ \underbrace{b_{9}\ b_{8}}_{\text{I(2)}}\ \underbrace{b_{7}\cdots b_{0}}_{\text{D(8)}}$$
**寻址方式（由 I 决定）：**

- I=00：直接/零变址（EA = D，按地址宽度零扩展）
    
- I=01：用变址寄存器 X1（EA = (X1) + D）
    
- I=10：用变址寄存器 X2（EA = (X2) + D）
    
- I=11：相对寻址（EA = (PC) + signext(D)）
    

  

> 说明：相对寻址里 **D 是 8 位补码位移**，要先做符号扩展 signext(D) 到 16 位再与 PC 相加。

> 本题 D 都是 0x20/0x44/0x22/0x21（最高位为0），所以都是**正位移**，符号扩展后数值不变。

  

**给定寄存器：**

- (PC)=1234H
    
- (X1)=0037H
    
- (X2)=1122H
    

---

## **2. 统一的拆字段方法（依据）**

  

对任意指令字 IR（16位）：

- OP = IR \gg 10
    
- I = (IR \gg 8)\ \&\ 0x3
    
- D = IR\ \&\ 0xFF
    

  

（“>>”右移，“&”按位与）

---

## **3. 四条指令逐条计算 EA**

  

### **(1) 指令：4420H**

  

**拆字段：**

- D = 0x20
    
- I = 00（因为高字节 0x44 = 0100 0100，OP(6)=010001，I(2)=00）
    

  

**I=00 ⇒ 直接/零变址：**

EA = 00\text{20H}

  

✅ **EA = 0020H**

---

### **(2) 指令：2244H**

  

**拆字段：**

- D = 0x44
    
- I = 10
    

  

**I=10 ⇒ 用 X2 变址：**

EA = (X2) + D = 1122H + 0044H

逐位相加：

- 0x22 + 0x44 = 0x66（无进位到高字节）
    
- 0x11 保持
    

  

EA = 1166H

  

✅ **EA = 1166H**

---

### **(3) 指令：1322H**

  

**拆字段：**

- D = 0x22
    
- I = 11
    

  

**I=11 ⇒ 相对寻址：**

先符号扩展：D=0x22，最高位为0 ⇒ signext(D)=0x0022

  

EA = (PC) + signext(D) = 1234H + 0022H

逐位相加：

- 0x34 + 0x22 = 0x56（无进位）
    
- 0x12 保持
    

  

EA = 1256H

  

✅ **EA = 1256H**

---

### **(4) 指令：3521H**

  

**拆字段：**

- D = 0x21
    
- I = 01
    

  

**I=01 ⇒ 用 X1 变址：**

EA = (X1) + D = 0037H + 0021H

逐位相加：

- 0x37 + 0x21 = 0x58
    

  

EA = 0058H

  

✅ **EA = 0058H**

---

## **4. 最终答案汇总**

- (1) 4420H：**EA = 0020H**
    
- (2) 2244H：**EA = 1166H**
    
- (3) 1322H：**EA = 1256H**
    
- (4) 3521H：**EA = 0058H**
    

---

### **小提醒（为什么我这样取 PC）**

  

这题对相对寻址只给了“(PC)=1234H”，**没有额外说明“PC是否已自增到下一条指令”或“指令长度导致 PC 要 +2”**。在组成原理常见题型里，默认就是**用题目给定的 (PC) 直接作为相对基址**来算 EA，因此得到 **1256H**。

  

如果你们课本/老师强调“相对寻址以**下一条指令地址**为基址”，且该指令为16位（2字节）并且 PC 为字节编址，那么第三问会变成：

EA=(PC+2)+0022H=1236H+0022H=1258H

你可以对照课程讲义定义确认一下即可。

24. 某计算机A有60条指令 ,指令的操作码字段固定为6位,从000000-111011,该机器的后续机型B中需要增加32条指令,并与A保持兼容,
(1)试采用操作码扩展方法为计算机B设计指令操作码.
(2)计算计算机B中操作码的平均长度.
解：(1) 因为计算机B要与计算机A兼容所以计算机A中的指令得保留：所以000000-111011为A的操作码部分。操作码字段的11100-111111的取值将作为扩展标识，将操作码扩展到地址字段,只需要占用地址字段3位即可表示新的32条指令。
(2)由(1)可知，有60条指令的操作码为6位，32条指令的操作码为9位,所以平均长度为：(606+3211)/92=7.74位

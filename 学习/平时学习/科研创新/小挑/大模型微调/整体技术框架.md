## 1) 识别部分：YOLO系列 + 跟踪/后分类

**目标**：在农场现场部署边缘端摄像头，低延时识别“异常征象”（如：鸡冠发紫、精神萎靡、腹泻污便、步态异常、异常呼吸、皮肤/羽毛病变等），并把**结构化结果**送给大模型。

- **模型选择**
    
    - **YOLO 系列**：优先选_你们熟_或有硬件加速的版本（如 YOLOv8/v9/v10/v11；你说的 YOLO12 若可用也行）。
        
    - **部署优化**：TensorRT / OpenVINO / onnxruntime-GPU，INT8 量化（Calibration 小心色差类征象）。
        
    - **对象跟踪**：ByteTrack / StrongSORT（稳定 ID，便于时间维度证据累积）。
        
    - **细粒度分类/二阶段**：对 YOLO ROI 送入轻量分类器（MobileNetV3 / EfficientNet-lite）对**具体症状**细分（如“水样腹泻 vs 粘稠绿色便”）。
        
- **边缘与云**
    
    - **边缘端**完成：推理、轻数据处理、抽象征象，上传**低带宽事件流**（JSON）。
        
    - **云端**完成：知识检索、推断、大模型生成、播报。

## 2) 识别信息如何与“大模型”交互（两层推断，稳健可控）

**核心思路**：不要把“是否得病”100%丢给大模型。用**可解释的中间层**做第一步推断，LLM 负责**解释、建议与行动指引**。

- **层 A：规则/图谱/贝叶斯融合（轻推断引擎）**
    
    - 建立**症状→疾病**的加权图谱（Ontology + Prior）。
        
    - 例如（简化示例）：
        
        - comb_color=purple → _缺氧/呼吸道病_ 权重 +0.6
            
        - watery_green feces → _新城疫/沙门氏菌/寄生虫_ 候选加分
            
    - 计算**候选集 Top-k** + **置信度**，并生成**机器可读证据链**。
        
- **层 B：禽类大模型（Instruct，多模态 + RAG）**
    
    - 输入：上面层 A 的**候选疾病 + 证据** + 环境/日龄/疫苗史 +（可选）帧图像。
        
    - 输出：**可能疾病排序**、为何如此、**应急处置步骤**、**观察要点**、**何时联系兽医**。
        
    - **注意**：让 LLM 遵循“不得做明确诊断，只给出**非医疗建议与紧急处置指引**”的合规话术。
        
- **对接方式**
    
    - **消息队列**：视觉服务发布 `detection.event`；推断服务订阅，产出 `triage.event`；LLM 订阅。
        
    - **REST/gRPC**：也可直接 POST 给 LLM 网关（vLLM/TGI/SGLang）统一走**工具调用**。

- **服务框架**
    
    - **推理服务器**：vLLM / TGI / SGLang（支持流式、并发、KV-Cache）。
        
    - **RAG 框架**：LlamaIndex / LangChain（向量库 Milvus / Weaviate / pgvector）。

## 4) “可打断”的**转语音**（TTS）与对话控制

**目标**：边合成边播报，**用户随时打断**（barge-in），可插话问“那要怎么隔离？”。

- **TTS 引擎（可选）**
    
    - **云**：Azure Neural TTS、Google Cloud TTS、Amazon Polly NTTS、ElevenLabs（均支持**流式**/SSML/多语种/音色），延迟低。
        
    - **本地/边缘**：Coqui-XTTS v2、Piper（轻量、离线，适合断网场景）。
        
- **关键实现**
    
    - **流式合成 + 播放**：服务端 SSML 分段合成（1–2 句一片段），客户端音频播放器**Chunk 播放**。
        
    - **VAD + ASR（可选）**：一旦检测到用户发声或点击“打断”，**立刻停播**并把当前问题送到 LLM。ASR 可用 **Whisper-large-v3**（离线）或云端识别。
        
    - **多说话人/情绪**：紧急场景上调语速与音量，SSML `<prosody rate="fast" volume="+2dB">`。
        
    - **双通道**：播报同时在 UI 展示**可点选步骤卡片**（允许用户直接跳到“消毒流程”）。

## 6) 置信度融合（把“看见”与“知识”合起来）

给你一个**简单而实用**的融合公式（层 A 用）：

- 记：来自检测/分类的症状集合 S={si}S=\{s_i\}，每个置信 p(si)p(s_i)。
    
- 先验：疾病 dd 的症状条件概率 P(si∣d)P(s_i|d)（由知识库/统计估计）。
    
- 似然（朴素贝叶斯）：
    

log⁡P~(d∣S)∝log⁡P(d)+∑iwi⋅[p(si)⋅log⁡P(si∣d)]\log \tilde{P}(d|S) \propto \log P(d) + \sum_i w_i \cdot \big[p(s_i)\cdot \log P(s_i|d)\big]

- 归一化得到 Top-k，输出给 LLM。
    
- **优点**：可解释、可热更新（wiw_i 反映症状重要度），LLM 负责**语言解释与行动方案**。

## 7) MVP 开发顺序（4 周快跑版）

1. **Week 1**：YOLO 推理 + 规则表（10–15 个高频病害/症状），事件流 JSON；前端摄像头→帧→推理→事件流面板。
    
2. **Week 2**：接入 Qwen2.5-VL-Instruct（或 DeepSeek-VL），**无微调先跑**；小型 RAG（10 份权威 PDF/手册）。
    
3. **Week 3**：流式 TTS + 打断（VAD/按钮即停），前端播报/卡片。
    
4. **Week 4**：微调小样本（LoRA 1–2k 指令），症状→处置模板优化，加入**安全/合规话术**与**不确定性处理**。

## 12) 评测与监控

- **视觉**：mAP@症状类别、F1、误报率；**时序稳定性**（Track-ID 抖动）。
    
- **推断**：Top-k 命中率、加权 NDCG、医生/饲养员打分。
    
- **LLM**：事实一致性（和知识库）、**有害建议率=0**、不确定性表达规范率。
    
- **TTS**：首包延迟、打断响应时间、可懂度主观评分（MOS-like）。
    
- **端到端**：从“异常出现”到“第一句话播报”的 P50/P95。
